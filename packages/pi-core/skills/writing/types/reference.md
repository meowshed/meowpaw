<role>
A reference serves a reader looking one fact up. It has no narrative, and every
item has the same shape so the reader learns the layout once and finds any
item.
</role>

<rules name="sections, in order">
1. Item: Give each item its name or path and a one-sentence description of what
   it does.
2. Parameters: List the parameters in a table with type, whether each is
   required, and its constraint, written as a rule a reader can check: "ISO
   8601 timestamp, at most 90 days ago".
3. Example: Show one realistic request and its response, copyable as they
   stand.
4. Errors: List each error with its exact text, its cause and what to do about
   it, because a reader arrives here holding the error.
</rules>

<rules name="done">
It is done when every item carries the same parts in the same order, and a
reader can answer their question from the item alone.
</rules>
