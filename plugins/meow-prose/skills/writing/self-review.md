# Self-review

Run these before a text is published, in this order: structure first, because
reordering sections invalidates sentence edits, then tone, then words, then
mechanics. A "no" to any check means edit before you publish.

## Structure

- List the terms the text introduces in order of first use. Is each one
  defined at or before its first use?
- Read only the headings. Do they tell the story?
- Does the first paragraph use a name the reader doesn't already know?
- Does any sentence on the main path point forward to a later section?
- Does every section open with a summary of itself?
- Does the text have every part its document type requires?
- Does any table cell hold an argument rather than a fact? Move the argument
  into a paragraph.

## Tone

- Does the first sentence answer the reader's question?
- Does every decision carry its reason?
- Read the heaviest paragraph aloud. Does it sound like a person explaining,
  or like a set of pronouncements?
- Are there runs of sentences under ten words? Join the ones that share a
  cause.
- Count the sentences over 35 words. More than one per thousand words means
  edit, because reading aloud does not catch them.
- Count "rather than", "instead of" and ", not". More than one per five
  hundred words is the rather-than pattern.
- Does any sentence read as a proverb, a paradox or a punchline? Put its
  reason back.
- How many paragraphs open in bold? More than one per section means edit.
- Search for: things, worth, "One ", "This document", "These notes",
  "Nothing ", "Nobody ", "None ", a sentence opening "That ", matters,
  "earlier draft", "a person", honest, shape. Each hit is a pattern from
  `patterns.md`.
- Does the summary read as prose a manager could forward, or as a list of
  theses?

## Words

- Circle every noun ending in -tion, -ment, -ance or -ity. Can it become a
  verb?
- Search for: mechanism, functionality, capability, solution, "there is",
  "in terms of", "the fact that".
- Search for: simply, just, easily, robust, seamless, leverage, delve,
  crucial.
- In Russian, search for: `является`, `осуществляет`, `данный`, `в рамках`,
  `с целью`, `представляет собой`.
- Does every technical term appear under exactly one name?
- Search for: may, should, "e.g.", "i.e.", "etc.", and any phrasal verb or
  idiom. Replace each with its one-meaning form.
- Find every stack of three or more nouns, and every pronoun with two
  possible antecedents.
- Did any cut drop a reason, a constraint or a number? Put it back.

## Mechanics

- Is the reader "you" for their actions, and is the component named for its
  own?
- Does every code block have a lead-in sentence, a language tag and a
  sentence after it?
- Is every character outside quoted code ASCII?
- Is the spelling the one the repository declares, with every technical term
  and every quotation left in its own?
