<role>
Run these before a text is published, in this order: structure first, because
reordering sections invalidates sentence edits, then tone, then words, then
mechanics. A "no" to any check means edit before you publish. Stop when every
check is answered yes, or when each "no" has been edited away.
</role>

<steps name="structure">
1. List the terms the text introduces in order of first use. Is each one
   defined at or before its first use?
2. Read only the headings. Do they tell the story?
3. Does the first paragraph use a name the reader doesn't already know?
4. Does any sentence on the main path point forward to a later section?
5. Does every section open with a summary of itself?
6. Does the text have every part its document type requires?
7. Does any table cell hold an argument rather than a fact? Move the argument
   into a paragraph.
</steps>
<steps name="tone">
1. Does the first sentence answer the reader's question?
2. Does every decision carry its reason?
3. Read the heaviest paragraph aloud. Does it sound like a person explaining,
   or like a set of pronouncements?
4. Are there runs of sentences under ten words? Join the ones that share a
   cause.
5. Count the sentences over 35 words. More than one per thousand words means
   edit, because reading aloud does not catch them.
6. Count "rather than", "instead of" and ", not". More than one per five
   hundred words is the rather-than pattern.
7. Does any sentence read as a proverb, a paradox or a punchline? Put its
   reason back.
8. How many paragraphs open in bold? More than one per section means edit.
9. Search for: things, worth, "One ", "This document", "These notes", "Nothing
   ", "Nobody ", "None ", a sentence opening "That ", matters, "earlier draft",
   "a person", honest, shape. Each hit is a pattern from `patterns.md`.
10. Does the summary read as prose a manager could forward, or as a list of
   theses?
</steps>
<steps name="words">
1. Circle every noun ending in -tion, -ment, -ance or -ity. Can it become a
   verb?
2. Search for: mechanism, functionality, capability, solution, "there is", "in
   terms of", "the fact that".
3. Search for: simply, just, easily, robust, seamless, leverage, delve,
   crucial.
4. In Russian, search for: `является`, `осуществляет`, `данный`, `в рамках`, `с
   целью`, `представляет собой`.
5. Does every technical term appear under exactly one name?
6. Search for: may, should, "e.g.", "i.e.", "etc.", and any phrasal verb or
   idiom. Replace each with its one-meaning form.
7. Find every stack of three or more nouns, and every pronoun with two possible
   antecedents.
8. Did any cut drop a reason, a constraint or a number? Put it back.
</steps>
<steps name="mechanics">
1. Is the reader "you" for their actions, and is the component named for its
   own?
2. Does every code block have a lead-in sentence, a language tag and a sentence
   after it?
3. Is every character outside quoted code ASCII?
4. Is the spelling the one the repository declares, with every technical term
   and every quotation left in its own?
</steps>
