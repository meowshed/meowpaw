<role>
A how-to guide serves a reader who already knows their goal and wants the steps
to reach it. It assumes the concepts and spends no words teaching them.
</role>

<rules name="sections, in order">
<rule id="goal">Title it with the goal as a verb phrase, "Rotate the signing
key", so a reader scanning a list finds it.</rule>
<rule id="prerequisites">List what must be true before the first step: access,
versions, a prior setup, because a missing prerequisite fails on step four with
an error that names none of it.</rule>
<rule id="steps">Number the steps in the order the reader performs them, one
action each, with the command or the setting in code font and a warning before
any step that is hard to undo.</rule>
<rule id="result">State what the reader should see when it worked, so they know
they are done.</rule>
<rule id="failures">Cover the failures a reader actually hits, each as the
message they see, its cause and the fix.</rule>
</rules>

<rules name="done">
<rule id="done">It is done when a reader with the prerequisites finishes
without leaving the page, and recognises both success and the common
failures.</rule>
</rules>
